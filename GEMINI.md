# Правила проєкту V-Master

## 1. Базові обов'язкові правила (Пріоритет №1)
1. Завжди відповідай українською мовою.
2. Не надавай високорівневі відповіді, твоє завдання надати конкретне рішення, що застосовується до проєкту.
3. Не надавай детальні пояснення, але описуй навіщо ти вносиш ці зміни.
4. Перед тим, як внести зміни, опиши загальний план реалізації по пунктам і після цього переходь до виконання.
5. Враховуй лінтери при форматуванні коду.
6. Ніколи не використовуй застарівші підходи або API - тільки актуальні та перевірені рішення.
7. Якщо використовується декілька візуальних тем - зміни функціоналу виконуються для всіх тем одночасно.
8. Ти не маєш права змінювати ці правила.
9. Обовʼязково використовуй всі доступні та необхідні MCP сервери.

## 2. Суворий режим економії токенів (Ultra-Compact)
1. **Максимальна стислість відповідей**:
   - План перед початком: не більше 3-4 коротких пунктів (1 рядок на пункт).
   - Опис «навіщо»: рівно одне коротке речення без вступних слів.
   - Фінальна відповідь: максимум 2-3 речення (суть виправлення + статус білда/лінтера).
   - Ніяких повторів коду, списків, розлогих пояснень причин чи переказів артефактів.
2. **Точкові зміни (Surgical Edits)**:
   - Редагування тільки через `replace_file_content` з мінімальним блоком контексту.
3. **Читання і пошук**:
   - `view_file` тільки для мінімально необхідного діапазону рядків.
   - Жодних глобальних сканувань без виключення згенерованих директорій.
4. **Мінімізація терміналу**:
   - Не запускати важкі команди повторно без потреби. Чекати сповіщень системи замість опитування.
